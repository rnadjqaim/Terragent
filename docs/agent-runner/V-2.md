# v-2: policy and risk layer

v-2 turns the runner from a command prototype into a governance prototype.

terraform, opentofu, and terragrunt focus on defining and executing infrastructure. terragent focuses on controlling whether that execution should be allowed.

## added value

### source policy scan

the runner can scan terraform source before scheduling work. this catches common dangerous patterns early:

- public ssh from `0.0.0.0/0`
- public rdp from `0.0.0.0/0`
- public s3 acl usage
- rds resources without an explicit encryption setting
- committed secrets in `.tf` or `.tfvars`

blocking findings stop the run before plan/apply work is scheduled.

### risk scoring

each run now returns a risk level:

- low
- medium
- high
- critical

critical risk means the run is blocked. medium and high risk can be used later for approval routing.

### blast radius summary

each policy-scanned run includes a compact blast-radius summary:

```text
files scanned
resources observed
security findings
secrets found
protected resource hints
```

this gives reviewers a fast view of how much infrastructure a run could affect.

### ci json output

the command supports machine-readable output:

```text
terraform agent-runner plan -source=infra -policy-scan -json
```

ci systems can use the `decision`, `risk`, `findings`, and `blast_radius` fields to pass, warn, or fail a pipeline.

## examples

human output:

```text
terraform agent-runner plan -source=infra -policy-scan
```

ci output:

```text
terraform agent-runner plan -source=infra -policy-scan -json
```

normal mock runner without source policy scan:

```text
terraform agent-runner plan -workspace=payments-prod
```

## v-3 direction

- parse real terraform plans instead of static source patterns
- add approval routing by risk and environment
- support terraform and opentofu engine selection
- store run history in a durable local or remote backend
- sign approved plan artifacts before apply
